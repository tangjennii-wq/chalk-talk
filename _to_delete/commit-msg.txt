The deploy made callCritique forward the tools. Three things then threw the
answer away before it could reach the user:

  * generation_workflow.js returned {text, modelUsed, usage} out of the critique
    step. callAnthropicText had already computed webSearched; the step dropped it.
  * finalize reported draft.webSearched. callDraft passes tools:null BY DESIGN
    (920773e) — search belongs to the review, not in front of the first token —
    so that value is structurally false forever.
  * the legacy waitUntil critique was called with five arguments and never
    received the tools at all.

Net effect on the free tier, which is durable-only: the review really did search
society sites and journals, and the talk recorded _webSearched: false and showed
no hourglass. The verification step would have read false and been blamed on the
tools not arriving.

The hourglass had a second, separate cause: S.reviewLiveChecking was set in one
place, inside the synchronous/BYOK branch. The durable path never touched it.
Both durable stage handlers now raise it from topicNeedsLiveCheck(S.topic) — the
same predicate the submit uses to decide whether to send tools — so the two
cannot drift. Cleared wherever generation stops, so a stale true cannot leak into
the next run.

test_live_check.mjs passed through all of this. It pattern-matches index.html,
and the client half was always correct. test_live_check_propagation.mjs executes
the workflow instead and asserts the record finalize writes: it fails 5 of its 9
assertions against the tree as it stood at 5ea4dd5, each naming a distinct
defect. The other four were killed by targeted mutation.

One assertion in test_gemini_safety.mjs required exactly
`webSearched: !!draft.webSearched` — it was pinning the bug as the spec, which is
why the suite stayed green. Rewritten to assert the contract.
