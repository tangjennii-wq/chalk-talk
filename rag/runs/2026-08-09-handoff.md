## How this codebase lies to you

Five instances in two days. All the same shape: **a claim that was never checked against the
mechanism it names.**

1. A comment said "we ALWAYS search the web while drafting (`S.wantWebSearch` is pinned true)".
   Nothing ever set it true. Every talk was drafted without live sources.
2. `.composer-bubble` positioned itself with `env(keyboard-inset-height)` — a Chromium API — with a
   comment claiming the iOS keyboard bug was fixed. On iOS it always resolved to the `0px` fallback.
3. A 16px anti-zoom rule scoped to `.app`, commented as preventing iOS zoom. Modals render to
   `document.body`, outside `.app`.
4. `receipt_issue` is declared `returns void`; PostgREST answers 204; `res.json()` threw on the empty
   body. Minting "failed" *after* inserting the row, and the error handler deleted the receipt and
   refunded the credit. The free tier could never have worked.
5. `test_mobile_ux.mjs`: 16 of 18 assertions still passed after deleting the feature they name.

**Working rules that came out of this:**

- When a comment says something is handled, check that the named mechanism exists on the platform it
  claims to handle.
- **Mutation-test every new assertion.** Break the thing deliberately; if the test still passes, it is
  not testing anything. This caught real gaps repeatedly and is cheap.
- Slices lie. Asserting over a narrow window of a 15k-line file (or `head -18` plus `tail -17` of a
  suite list, which do not meet) produces confident false negatives.
- `node --check` cannot see scope. Two production hangs came from an orphaned local and a function
  nested inside `render()` — both parse fine. **Set up `eslint no-undef` over the inline scripts.**
  Ten minutes; would have caught both.
- Do not let two agents edit `index.html` at once. It happened three times; nothing locks the file,
  and the later writer silently wins.
